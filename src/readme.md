# Контекст проекта Test1Application

## 1. Цель проекта

Учебное Java-приложение для последовательного изучения:
- REST API;
- Spring Boot;
- Spring Data JPA;
- аннотаций Spring и JPA;
- внедрения зависимостей (Dependency Injection);
- взаимодействия слоёв приложения.

Приложение предназначено для обучения. Работа ведётся небольшими последовательными шагами с разбором смысла каждого действия.

## 2. Текущее состояние проекта

Реализованы:
- сущность `User`;
- перечисление `Sex`;
- `UserRepository`;
- `UserService`;
- база данных H2;
- класс запуска `Test1Application`;
- класс `DatabaseInitializer` в пакете `config`.

В сущности `User` переопределён метод `toString()`.

В `UserService` уже существует метод:

`public List<User> findAll()`

Он возвращает результат `repository.findAll()`.

Также существуют методы:
- `createUser()`;
- `updateUser()`.

## 3. Архитектурные решения

### Разделение ответственности

Принято следующее распределение:

- `Test1Application` — точка входа, запуск Spring Boot.
- `DatabaseInitializer` — первоначальная инициализация демонстрационной базы.
- `UserService` — бизнес-логика и проверка соответствия данных контракту.
- `UserRepository` — взаимодействие с базой данных.
- `User` — сущность пользователя.

### Почему DatabaseInitializer использует UserService

Принято решение создавать демонстрационных пользователей через `UserService.createUser()`, а не напрямую через Repository.

Причина: данные должны соответствовать бизнес-правилам и контракту независимо от источника создания.

Инициализация базы не должна обходить проверки, применяемые при обычном создании пользователей.

### Почему используется CommandLineRunner

`DatabaseInitializer` реализует `CommandLineRunner`.

Spring Boot автоматически вызывает метод `run()` после запуска приложения и создания Spring-контекста.

Это позволяет выполнять первоначальную инициализацию базы без размещения дополнительной логики в `Test1Application`.

## 4. DatabaseInitializer

Класс находится в пакете `config`.

Используются:
- `@Component`;
- `implements CommandLineRunner`;
- внедрение зависимостей через конструктор.

Зависимости:
- `UserService`;
- `UserRepository`.

Текущая реализация метода `run()`:

```java
@Override
public void run(String... args) throws Exception {
    repository.truncateTable();

    userService.createUser(
        new User("Sergey", "Ivanov", 23, Sex.MALE)
    );

    userService.createUser(
        new User("Marina", "Ozernaya", 55, Sex.FEMALE)
    );

    userService.createUser(
        new User("Jozef", "Burkly", 65, Sex.MALE)
    );
}
```

Примечание: в первоначальном варианте была опечатка `Sex.FMALE`, исправленная на `Sex.FEMALE`.

## 5. Очистка демонстрационной базы

В `UserRepository` добавлен метод:

```java
@Modifying
@Transactional
@Query(
    value = "TRUNCATE TABLE users RESTART IDENTITY",
    nativeQuery = true
)
void truncateTable();
```

Причина выбора:
- каждый запуск приложения должен начинаться с чистой таблицы;
- предыдущие демонстрационные записи удаляются;
- счётчик ID сбрасывается.

Проверять, пуста ли таблица, не требуется: принято решение принудительно приводить её к исходному состоянию при каждом запуске.

Важно: `TRUNCATE` является DDL-операцией, поэтому не следует рассчитывать на обычную транзакционную откатность этой операции.

Такой подход подходит для учебной демонстрационной базы, но не для базы с пользовательскими данными.

## 6. Работа с enum Sex

При проверке таблицы H2 обнаружено, что значение `sex` сохраняется числом — позицией элемента enum.

Причина: стандартное поведение JPA при отсутствии явного указания способа хранения enum — `ORDINAL`.

Принято решение перейти на строковое хранение.

В сущности `User` необходимо использовать:

```java
@Enumerated(EnumType.STRING)
private Sex sex;
```

Импорты:

```java
import jakarta.persistence.Enumerated;
import jakarta.persistence.EnumType;
```

Причина выбора STRING:
- в БД сохраняются `MALE` и `FEMALE`;
- изменение порядка элементов enum не приводит к неправильной интерпретации сохранённых значений;
- данные становятся понятнее при просмотре таблицы H2.

Изменение необходимо проверить после перезапуска приложения.

## 7. Целевое состояние приложения

При запуске приложение должно выполнять следующий сценарий:

1. Запуск Spring Boot.
2. Автоматический вызов `DatabaseInitializer.run()`.
3. Очистка таблицы `users`.
4. Создание демонстрационных пользователей через `UserService.createUser()`.
5. Получение списка пользователей через `UserService.findAll()`.
6. Вывод всех пользователей в консоль.

Для вывода использовать существующий `toString()` класса `User`.

Логика вывода должна находиться в `DatabaseInitializer`, а не в `Test1Application`, поскольку инициализатор отвечает за подготовку демонстрационной базы.

## 8. Незавершённые задачи

Приоритет выполнения:

1. Добавить `@Enumerated(EnumType.STRING)` к полю `sex` в `User`.
2. Проверить строковое хранение enum в H2.
3. Дополнить `DatabaseInitializer.run()` получением списка пользователей и выводом в консоль.
4. Запустить приложение и проверить полный сценарий.
5. Проверить повторный запуск: таблица очищается, ID начинаются заново, пользователи создаются без дубликатов.

После завершения этого этапа продолжить изучение REST и Spring Boot.
